# R8 恢复 pilot 的逐部件支持规模审计

日期：2026-11-22  
对象：`recovery_paired_bound_v3_r8_20261122`  
范围：train / validation 标签可用性与规模规划。sealed test 结果行解码数为 0。

## 1. 方法

1. 直接证据：新 v3 R8 pilot 的 30 个 train 和 15 个 validation 工况，只统计 `p_hit_mask=true` 的单元。
2. 规模规划证据：旧 R32 参考开发集的 240 个 train 和 60 个 validation 工况。该数据只用开发分割的 `p_hit_success_count` 和 `p_hit_trial_count`；未读取 test 结果。
3. R8 等效正例率：对每个 R32 工况中的成功数 `k`，计算从 32 次重复中无放回取 8 次至少包含一次成功的概率：

   `p8(k) = 1 - C(32-k, 8) / C(32, 8)`。

   再对 300 个开发工况求平均。这保留了 R32 中已观察到的工况异质性，不为零命中工况虚构成功。
4. 不确定性：对 300 个开发工况做 20,000 次非参数 bootstrap，报告 R8 等效率的 2.5%--97.5% 分位。二项分布通过概率仅用于预算规划；Sobol 设计点不是独立同分布随机样本。

## 2. 主要结果

- 67 个部件的 R8 等效正例率最小/中位/最大值为 0.00848 / 0.08628 / 0.65812。
- 限制规模的部件是 `component-020`。它在新 R8 pilot 中为 0/45；在历史 R32 开发集中为 4/300，4 个工况的成功数分别为 1、2、6、32。
- `component-020` 的 R8 等效正例率为 0.008483，bootstrap 95% 区间为 [0.000833, 0.018972]。
- 按点估计，2000 个 train 只期望获得 16.97 个 `component-020` 正例，达到 20 个正例门槛的概率为 0.2603。300 个 validation 只期望获得 2.55 个正例，达到 5 个门槛的概率为 0.1141。两门同时通过的点估计概率为 0.0297。
- 在 2000/300 规模下，预期通过全部支持门的部件为 64.62/67；8 个部件的 train+validation 联合通过概率低于 0.95。

## 3. 规模决策

`2000 train / 300 validation` 不足以支持 67 个部件的全任务入场。

按历史开发证据的点估计：

- 使每个部件单独以至少 95% 概率通过 train `positive>=20, negative>=20` 门，需要最多 3,282 个 train。
- 使每个部件单独以至少 95% 概率通过 validation `positive>=5, negative>=5` 门，需要最多 1,077 个 validation。
- 用 Bonferroni 将 67 个部件的支持门家族失败概率控制在 5% 以内，点估计需要 4,385 个 train 和 1,785 个 validation。
- 选用 4,400 train / 1,800 validation 时，点估计的全部件联合通过概率下界为 0.9986；5,000/2,000 时为 0.9998。

bootstrap 下界反映了稀有部件证据量不足：`component-020` 只由 4 个 R32 工况支撑，其 95% 下界会将任何实用规模的保守通过概率压至很低。因此采用两层决策：

1. **当前全部件 Reference 候选：**预注册 5,000 train / 2,000 validation，为点估计留出余量。test 规模由冻结后的评估精度目标单独决定。
2. **计算预算优先方案：**生成不少于 2,000/300 的 Reference 集，只对实际满足 train 和 validation 正负支持门的部件冻结任务入场集。不满足门槛的部件保留标签与识别区间，不进入当前点预测模型的独立验收。

后续的稀有部件富集应基于冻结的前结果几何代理和独立种子确认。当前 X1/X2 暴露均衡臂未通过预注册门，不用其替代 Reference 验证分布。

## 4. 可复核结论

- v3 已解决大面积标签删失；当前主要瓶颈转为 Reference 分布下的稀有几何可达性。
- 2000/300 可用于训练和评估预注册的部件子集，不足以支持“67 个部件全部入场”的结论。
- 要维持全部件任务，当前最合理的 R8 点估计规模是 5,000/2,000，并在生成后依据已冻结门槛审计；支持门不通过时保留任务子集作为当前可训练范围。

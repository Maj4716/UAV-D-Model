# 对“毁伤域稀疏成因”现有证据的怀疑主义审查

> 日期：2026-10-21  
> 范围：审查 `ml_stats_audit`、`axis_geometry_necessity_audit` 与 `factorial_direction_source_counterfactual` 的论证强度。本文不评价真实武器效能，也不认可任何尚未标定的毁伤树或源项参数。

## 审稿结论

现有证据足以推翻“5000 例中的恒零已经证明该任务在一切合理条件下必然稀疏”这一说法，也足以把**固定入射几何与 Taylor 源轴的组合**列为当前软件链中的首要近因。证据尚不足以证明 `+body-X` 才是物理正确方向，也不足以证明真实项目并不存在内生稀疏。总报告应采用下面这一更窄、可证伪的结论：

> 当前极端不均衡是**特定、未验证的仿真设计元组**下的条件性结果；在现有证据中，人为设定与方法选择对严格零和极端稀疏具有主导性影响。真实可接受任务域中是否仍然稀疏，必须在坐标合同、可行攻击包线、源项、目标响应和 KMFC 语义分别获准后重新估计。

## 已被直接证据支持的判断

1. **当前归档对方向效应不可辨识。** 5000 例只有一个速度方向和一个姿态；`y-z`、速度和三档弹型覆盖较充分，并不能补偿方向与姿态自由度缺失。
2. **零发生的位置可以分层定位。** C 候选类别在 5000 例中于部件命中阶段即为 `0/5000`；旧 K 输出恒零，而候选 K 部件存在 28 例上游信号。这说明 C 的严格零首先是上游可达性问题，K 的旧标签还受部件映射/树定义影响。
3. **当前已实现射线族存在明确几何排除。** 对已观察的 `direction_x<0` 射线，从两个负 x 接触面继续向更负 x 传播时，绝大多数内部 K/F/C 部件在 AABB 必要条件上即不可达；该结论是条件于接触面和射线方向的数学结论。
4. **源轴符号在当前 dev3 引擎中具有强因果敏感性。** 配对保持入射点、速度、姿态、弹型和随机种子不变，只将 `axis_body` 从 `-X` 改为 `+X`，当前 `+X` 入射代理的 C 支持在 27 对中全部从 `0` 变为 `1`，K/F 各有 21 对从 `0` 变为 `1`。这足以证明软件输出并非对这一人为设定稳健。
5. **“只把战斗部做大”不是当前严格零的优先修复。** 在同一源轴下，三档弹型显著改变命中数量和剂量规模，但“是否出现任一类别支持”远不及源轴翻转敏感。该结论只适用于当前源项和响应模型。
6. **零锚定门控不能从零剂量产生客观正样本。** `e/(e+T)` 在三种尺度下保持正支持集合不变。这是门函数的结构性质，可用于否定“仅改平滑阈值即可修复上游零”的方案。

## 总报告必须降级或限定的表述

### 1. 不能把诊断用源轴翻转直接称为“物理修复”

源轴是战斗部模型的一部分。翻转它确实证明结果对建模选择敏感，却同时改变了弹型的方向性定义。由于 `-body-X` 与 `+body-X` 哪一个符合原始弹体坐标、起爆位置和 Taylor 环定义尚未由独立资料确认，试验只能证明**软件模型空间中的非必然性**，不能单独证明真实任务域中的非必然性。

建议用语：`源轴坐标语义是最高优先级待核验项；+X 反事实不是建议参数。`

### 2. dev1 归档与 dev3 反事实之间存在版本桥接缺口

5000 例正式归档记录的引擎版本为 `0.7.0.dev1`，反事实运行使用 `0.7.0.dev3`。反事实内部配对因果有效，但不能把 dev3 的效应大小直接当作 dev1 归档稀疏的精确反事实。正式结论应并列报告：

- dev1：描述性归档事实；
- dev3：受控机制敏感性；
- 二者之间：需要以冻结代码、目标、注册表和候选账本重建一个可复现基线后才能闭合。

### 3. 六面合并比例不是作战毁伤率

六个正交面、规则九点网格和固定 120 m/s 是诊断设计，没有给出真实攻击方向的概率测度。底向上攻击很可能不属于巡飞弹的实际包线；其余面也不应等权。24 个未命中候选虽然未入分母且两源轴条件保持配对，但仍说明面间支持不同。`10.0%/32.0%/8.7%/6.0%` 与翻轴后的比例只能称为**该诊断候选集上的支持率**，不能解释为真实发生概率。

### 4. “结构零”必须写清条件

Taylor 角的高斯展宽经 `[0,π]` 截断，理论支持并非严格限制在负 x 半空间；现有 6120 条 Train 破片轨迹全部为负 x，是极强的经验支持，却不是对所有随机抽样的形式化证明。AABB 排除仅对 `direction_x<0` 且从已审计接触面出发的射线成立。

建议区分：

- `归档观测零`：当前 5000 例中没有正值；
- `当前设计下的实际结构零`：有限 R 与极窄随机尾部下近似不可观测；
- `数学结构零`：在完整随机支持上严格不可能，目前尚未全面证明；
- `真实物理零`：需要外部标定，当前无证据。

### 5. 不能完全排除“威力不足”

现有试验可以排除的是：在当前低保真模型中，战斗部档案差异不是造成**严格几何零**的首因。它不能排除：

- 真实破片质量、速度、方向分布或装甲响应与当前未验证参数不同；
- 威力主要影响等级 1/2 跨阈率，而非是否触及部件；
- 二元“任一支持”指标存在饱和，掩盖剂量和严重度差异。

因此应写成“威力不是当前软件链严格零的领先近因，真实充分性仍未获验证”，不能写成“战斗部威力已经充分”。

### 6. 平滑门试验没有验证毁伤树合理性

正支持计数对 `e/(e+T)` 不变，在零锚定函数下几乎是定义上的必然结果。它证明门控不能创造上游信号，却没有比较等级边界、分支依赖、冗余逻辑、剂量聚合和校准误差。候选 KMFC 分组也是尚未批准的 v0 语义。毁伤树仍可能决定 M/F 的等级比例，并能通过重新定义合法部件集合改变 K 的支持；这一问题必须与上游几何零分开审查。

### 7. 当前置信区间和检验只宜描述性使用

`0/5000` 的二项上界需要独立同分布或明确抽样测度；当前案例可能共享条件簇、目标与参数实现，且每例仅 `R=2`。归档 Test 已被观察，探索性分组检验还存在多重比较和稀疏期望格。任何 Wilson 上界、p 值和划分差异都不得包装为确认性物理结论。

## 对三种竞争解释的审稿裁决

| 解释 | 当前证据裁决 | 可支持的最强表述 |
|---|---|---|
| 项目本性决定，必然极稀疏 | 未获支持 | 目标拓扑、关键部件小投影面积和系统冗余可能造成真实长尾，但当前单配置不能证明“必然” |
| 人为/方法因素造成 | 获得强软件内证据 | 固定方向/姿态、接触面与未核验源轴组合主导了当前严格零；树映射和 `R=2` 进一步制造或放大不可学性 |
| 两者共同作用 | 当前最合理 | 人为设定是已证实的近因；物理内生稀疏是仍待测量的剩余问题 |

## 关闭争议所需的最小试验

1. **坐标合同审查**：用原始设计资料、弹体剖面与三维射线可视化独立确认弹体 `+X`、速度、起爆点、Taylor 轴和角度正方向；在此之前不改生产源轴。
2. **版本闭合**：在同一冻结 dev3 配置下先复现一个 Reference 基线，再做全因子对照；不要把 dev1 归档与 dev3 反事实混成同一总体。
3. **定义可行攻击包线**：剔除物理/战术不可行方向，对允许方向设立有依据的参考测度；全部正式训练样本仍须朝向目标并通过首次接触合同。
4. **四因素受控设计**：`方向/姿态 × 源轴/源项模型 × 威力尺度 × 树版本`，共用候选账本和随机数；逐级记录接触、装甲侵彻、部件命中、沉积能、部件状态、树输出。
5. **提高机制识别的 R**：先对零附近工况做自适应重复和收敛检查，再判断是严格零还是 Monte Carlo 未观察；不要用扩大独立案例数代替单工况概率收敛。
6. **双数据流**：Reference/Validation/Test 服从冻结参考分布；仅 Train 可用稀有事件/重要性采样富集，并保存选择概率与设计权重。下一代 Test 必须重新封存。

只有当一个 KMFC 类别在获准攻击包线、获准源项与响应模型、获准树语义以及充分 R 下仍稳定稀疏，才能把剩余稀疏归因于项目本性。当前材料支持的是“人为因素主导、物理长尾尚未排除”，而不是两个极端中的任何一个。
